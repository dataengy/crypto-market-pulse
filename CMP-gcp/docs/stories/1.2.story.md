# Story 1.2: Scaffold `CMP-gcp/` + strict settings

## Story
As an implementing agent, I want one strict settings loader, so that every scalar comes from config and a missing key fails loudly (FR-2, AD-2).

## Boundaries
- **Always:** copy the shape of [`CMP-dbx-fe/src/cmp/settings.py`](../../../CMP-dbx-fe/src/cmp/settings.py) (`load_env`, `env`, `get`); `load_dotenv(..., override=False)`; config sections exactly as in [plan §Layout](../../../docs/plans/gcp/01-local-dev-debug.md#layout-cmp-gcp).
- **Never:** a dataclass with defaults; `os.getenv(x, d)`, `dict.get(k, d)` or `${X:-d}`; a shared library across lanes (copy, don't couple); the `cloud` profile values (they belong to `deploy/` — its keys stay present but empty in `.env.secrets.demo`).

## Acceptance Criteria
1. **Given** `profiles.local.window_s` is removed, **when** `load("local")` runs, **then** `ValueError` mentions `window_s` and `config/config.yaml`.
2. **Given** `CMP_PROFILE=bogus`, **then** `ValueError` names the profile and the file.
3. **Given** an env var already set in the shell, **then** the `.env` value does not override it.
4. `find_hardcoded_scalars.py src scripts --exit-nonzero-on-find` exits 0.
