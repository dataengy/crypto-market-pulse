# Story 3.1: Beam pipeline (event time, dedup, accumulating late panes)

## Story
As the builder, I want a streaming Beam pipeline that turns Pub/Sub trades into 1-minute bars with correct late-data and duplicate handling, so that the Beam path matches the SQL path (FR-7, AD-3…AD-6).

## Boundaries
- **Always:** `ReadFromPubSub(subscription, with_attributes=True, timestamp_attribute="event_time_ms", id_label="event_id")` → drop heartbeat → parse/validate with tagged `invalid` → `trades_quarantine` → key by symbol → `WindowInto(FixedWindows(window_s), trigger=AfterWatermark(late=AfterCount(1)), accumulation_mode=ACCUMULATING, allowed_lateness=allowed_lateness_s)` → `CombinePerKey(StatsCombine)` (output reuses `reference.compute_stats`) → add `window_start, pane_index, timing, emitted_at` → append to `trades_1m_beam_panes`. Log the effective runner at start.
- **Never:** DML/MERGE; `WriteToBigQuery` in the local profile (use `bq_sink.py` DoFn); Prism-specific flags ([ADR-0002](../adr/0002-directrunner-not-prism.md)); custom state/timers (the combiner is enough); a second copy of the aggregation math.
- TDD: [story 3.2](3.2.story.md) case 1 is written first and drives `build_windowed`.

## Acceptance Criteria
1. **Given** emulators + `sql-apply`, **when** `beam_run --profile local` runs and `produce --source fixture` is replayed, **then** `trades_1m_beam` BTCUSDT 10:00 = FX.
2. **Given** any run, **then** the first log line names the runner that actually executed (e.g. `BundleBasedDirectRunner` or `PrismRunner`).
3. **Given** a poison message, **then** one `trades_quarantine` row and the pipeline keeps running.
