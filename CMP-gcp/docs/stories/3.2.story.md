# Story 3.2: Deterministic TestStream suite

## Story
As a reviewer, I want windowing, lateness, dedup, poison and heartbeat behaviour pinned by deterministic tests, so that semantics never regress silently (FR-8, NFR-5).

## Boundaries
- **Always:** `TestStream` + `TestPipeline(options=StandardOptions(streaming=True))` + `assert_that`; explicit `advance_watermark_to`; expected values from `reference.compute_stats`; `window_s` / `allowed_lateness_s` read from `config/config.yaml` (tests may pass literals only via fixtures).
- **Never:** `time.sleep`, emulators or network in `tests/beam/`; asserting runner internals; snapshot files.

## Acceptance Criteria (cases from [plan §8](../../../docs/plans/gcp/01-local-dev-debug.md#s8))
| # | Test | Given / When | Then |
|---|---|---|---|
| 1 | `test_on_time_with_duplicate` | fixture (8 events, 1 dup), watermark → past 10:01 | BTCUSDT 10:00 = FX; ETHUSDT 10:00 count 1; BTCUSDT 10:01 count 1; ETHUSDT 10:01 count 1 |
| 2 | `test_out_of_order_same_bars` | the same events, shuffled arrival | identical bars to case 1 |
| 3 | `test_late_within_lateness_accumulates` | watermark past the window end, then 1 late trade within lateness | a 2nd pane `timing=LATE`, `pane_index=1`, totals = on-time + late (oracle on the union) |
| 4 | `test_late_beyond_lateness_dropped` | watermark past end + lateness, then a late trade | no new pane; bar unchanged |
| 5 | `test_poison_to_invalid` | one unparsable / invalid event | appears in the `invalid` output; other bars unchanged |
| 6 | `test_heartbeat_ignored` | heartbeat element present | no bar for the heartbeat's window |
