# Story 2.2: BigQuery SQL templates + emulator compatibility probe

## Story
As the builder, I want one set of GoogleSQL templates applied by one client to the emulator now and the cloud later, so that a local pass means something for the cloud (FR-5, AD-1).

## Boundaries
- **Always:** port `sql/bigquery/001–004` from the reference with `{{dataset}}` / `{{lookback_days}}`; add `002b_dq` and `005_1m_beam`. `001_raw` mirrors the subscription metadata columns (`subscription_name, message_id, publish_time, data BYTES, attributes`), `PARTITION BY DATE(publish_time)`. Dedup tie-break adds `message_id`; heartbeats filtered.
- **Never:** edit SQL to suit the emulator (mark it `skip_on_emulator` instead); a templating engine (`str.replace` on known keys is enough, and an unknown placeholder fails); DML.

## Acceptance Criteria
1. **Given** a template with an unknown `{{x}}`, **when** rendered, **then** `ValueError` names `x`.
2. **Given** the emulator, **when** `just sql-apply` runs, **then** every file either succeeds or is listed in `CMP-gcp/docs/emulator-gaps.md` with the failing function and `skip_on_emulator`.
3. **Given** `sql-apply` twice, **then** the second run succeeds (`CREATE … IF NOT EXISTS` / `CREATE OR REPLACE VIEW`).
