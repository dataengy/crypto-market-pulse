# Story 3.3: Debug tooling + Beam notebook

## Story
As a debugging agent, I want one-line recipes to inspect Pub/Sub, BigQuery and Beam stages, so that I can locate a failure in minutes (FR-9, UJ-2).

## Boundaries
- **Always:** recipes reuse the existing clients/config (`sql.client`, `.tmp/emulators.env`); pull **without ack** in `debug-pubsub`.
- **Never:** a debug CLI framework or a TUI; recipes that mutate state (except for clearly named `fault-*` ones in 4.2).

## Acceptance Criteria
1. `just debug-pubsub` lists topics/subs and shows up to N un-acked messages (N from config); a re-run shows the same messages.
2. `just debug-bq "<sql>"` prints rows from the emulator.
3. `just debug-beam` runs with `--direct_num_workers=1`, DEBUG logs and a `beam.Map(log)` tap after each stage.
4. The ported `02_beam_event_time.ipynb` executes inside `just test`.

## Tasks / Subtasks
- [ ] `justfile`: `debug-pubsub`, `debug-bq`, `debug-beam`.
- [ ] `notebooks/02_beam_event_time.ipynb` (port from the reference `notebooks/workbooks/`, import `cmp_gcp`).
- [ ] `tests/unit/test_notebooks.py::test_beam_notebook_executes` (same approach as the reference `test_workbooks.py`).

## Verification
`just debug-pubsub && just debug-pubsub` → same message ids; `just test -k notebook` → pass.
