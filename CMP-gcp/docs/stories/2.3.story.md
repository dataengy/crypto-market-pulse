# Story 2.3: BigQuery-subscription shim (local only)

## Story
As the builder, I want a tiny pull → insert → ack shim, so that the SQL path receives at-least-once raw rows locally the way a BigQuery subscription would (FR-6, ADR-0004).

## Boundaries
- **Always:** ack only after `insert_rows_json` returns no errors; same metadata columns as `001_raw`; batch size and timeouts from config; `--once` (drain then exit) for tests.
- **Never:** transform or dedup in the shim (the views do that); deploy or reference it from cloud code; retry logic beyond leaving messages un-acked.

## Acceptance Criteria
1. **Given** `produce --source fixture` into the emulator, **when** `bq_sub_shim.py --once` runs, **then** `trades_raw` has 8 trade rows + 1 heartbeat row, `trades_dedup` has 7, and `trades_1m` BTCUSDT 10:00 = FX.
2. **Given** an insert error (wrong dataset), **then** no message is acked and the shim exits non-zero with the BigQuery error.

## Tasks / Subtasks
- [ ] `tests/it/test_shim.py::test_fixture_lands_raw_and_dedup`, `::test_insert_error_no_ack` (`needs_emulators`).
- [ ] `scripts/bq_sub_shim.py` — `row_from_message(msg, subscription: str) -> dict` (pure; unit-tested) + the loop.
- [ ] `justfile`: `shim`.

## Verification
`just up && just sql-apply && just produce fixture && uv run python scripts/bq_sub_shim.py --once && just debug-bq "SELECT COUNT(*) FROM <ds>.trades_dedup"` → `7`.
