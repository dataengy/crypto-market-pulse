# Story 1.3: Core port + producer

## Story
As the builder, I want the domain core, the oracle and a producer with Pub/Sub attributes and a heartbeat, so that both paths get identical, event-timed input (FR-3, AD-3, AD-5).

## Boundaries
- **Always:** port `domain.py`, `bybit_ws.py` and the `Publisher` protocol from `CMP-dbx-fe/src/cmp/`, where ws settings already come from config. `domain.py` there still hardcodes the timestamp bounds (`946684800000…4102444800000`): move them to `domain.{min_ts_ms,max_ts_ms}` and pass them in as parameters. Leave the dbx-fe copy alone and note it for the backlog. Port `reference.py` (oracle) from dbx-fe as well. Copy the fixture `CMP-dbx-fe/tests/fixtures/trades.jsonl` (8 events, 1 duplicate).
- **Never:** a Kafka sink; retries or backoff beyond what `bybit_ws` already has; publisher batching tuning.

## Acceptance Criteria
1. **Given** the fixture, **when** `reference.compute_stats` runs on BTCUSDT 10:00, **then** FX: `trade_count=4, volume=0.45, open 70000, high 70010, low 69990, close 69990`.
2. **Given** `produce --source fixture --sink stdout`, **then** it prints 8 events + 1 heartbeat. Each event has attributes `event_id`, `event_time_ms`, `symbol`. The heartbeat has `kind=heartbeat` and `event_time_ms = max(event_time_ms) + window_s*1000 + allowed_lateness_s*1000 + 1000`.
3. **Given** `--replay 2`, **then** 16 events + 1 heartbeat.
